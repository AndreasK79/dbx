20. Double-Shift database object search
Pressing Shift twice quickly (JetBrains Search Everywhere style, within 400 ms, with no other key in between — so typing capitals never trips it) opens a search dialog scoped to the active database: it lists every table, view, materialized view, procedure, function, and trigger the connection type supports, and you filter by typing (same matching as Ctrl+P quick-open: exact → initials → prefix → pinyin initials → word-prefix → substring → fuzzy, with highlighted matches and type badges). Trigger support follows the connection's capabilities — MySQL-family and Kingbase/Xugu list database-wide triggers, PostgreSQL-family doesn't list them at the database level so they don't appear there. Selecting a table/view/materialized view opens it as a data tab; procedures, functions, and triggers open their source in an editor tab (Ctrl+P quick-open's open handlers are reused as-is, including overload signatures). The scope is the active tab's connection + database + schema + catalog, falling back to the active connection's configured database. Fix for schema-aware engines (postgres family, SQL Server, …): object listing is schema-scoped there (`n.nspname = ''` matches nothing), and a tab that never picked a schema produced a blank schema and therefore an empty list — the dialog now fans out over the database's schemas (parallel queries, capped at 50, a failing schema doesn't lose its siblings, error only when all fail) and merges the results, so the search covers the whole database; database-object-tree engines (dialect-less JDBC, mongodb) keep the single whole-database call. The schema list is filtered through the sidebar's own system-schema filter before the cap, because a postgres database carries one numbered pg_toast_N system schema per table, they sort ahead of every user schema, and the first 50 would otherwise all be empty system schemas. That also exposed an upstream blind spot: the shared postgres-like system-schema rules knew the exact name pg_toast and the pg_temp_/pg_toast_temp_ prefixes but not the numbered pg_toast_ prefix (the backend's hide-system catalog SQL misses it too), so numbered toast schemas leaked into the sidebar's schema tree and the schema picker — they're now classified as system everywhere. The gesture is observed on a window capture listener (so keydowns stopped by other handlers still reset it), resets on window blur, and does nothing while another dialog is open.

23. $0 final cursor position in snippets
VS Code-style $0 in a snippet body now marks where the cursor should land: `SELECT * FROM ${1:table} WHERE $0` puts the caret at the WHERE position once you've filled (or Tabbed past) the table field. ${1:default} tabstops with Tab/Shift+Tab navigation already worked — dbx snippets and the VS Code importer share that syntax — but CodeMirror's snippet engine has no $0 concept: a bare $0 was inserted literally, and ${0} sorted as the *first* field because fields order by number. $0/${0} are now renumbered to one past the highest tabstop, which is the final field in CodeMirror: Tab walks the numbered fields, then the cursor lands there and snippet mode ends, matching VS Code. Multiple $0 occurrences mirror into one final field (multi-caret). Only zero is translated — bare $1/$2 stay literal because they are PostgreSQL bind parameters, and \$0 stays a literal dollar.

26. Unfilled SQL parameters send NULL
Leaving a value empty in the run-query parameter dialog now substitutes NULL instead of an empty string literal: `WHERE name = :name` left blank matches nothing, instead of silently matching every row where name is the empty string. This covers the String kind (the default) and Boolean; Number and Null already rendered empty as NULL. Raw keeps its own contract — an empty Raw value still leaves the placeholder unresolved in the SQL, and typing `''` as Raw remains the way to send an explicit empty string. Typed whitespace is still data (a single space sends `' '`), and one placement is deliberately excepted: a placeholder embedded inside a larger string literal ('file_${name}.txt') still splices in nothing when empty, because NULL cannot live inside a literal; a placeholder that IS the whole literal ('${name}') renders NULL when empty. The value field's placeholder text now says "Enter value (empty sends NULL)" in both locales, so the rule is visible exactly when a field is empty, and the SQL preview below the table has always shown the resolved statement. Clear Values therefore also produces all-NULL parameters (Raw excepted).

28. A fully typed table/column name outranks a colliding snippet trigger
Typing a complete identifier (e.g. the table name `orders`) in the SQL editor no longer accepts a snippet instead of the identifier: the autocomplete ranks the exact table/column match first. Background: completion items score as match quality + per-type boost + exact-match bonuses, and a custom snippet whose trigger prefix exactly equals the typed word got a deliberate +40,000 "exact trigger = intent" bonus — designed for unambiguous triggers, but with hundreds of imported VS Code templates a trigger often equals a real table name, so the template owned the top spot and Tab inserted it. The exact-match pass now checks first whether any table or column item exactly matches the typed word; when one does, colliding snippets are demoted to plain ranking (their exact-trigger and exact-match bonuses are stripped; the base trigger boost stays, so the snippet still leads the non-exact pool right below the identifier instead of sinking). Scoped deliberately: an exact function name or keyword still yields to an exact snippet trigger (existing pinned behavior), a merely prefix-matching column still loses to the snippet, and when nothing collides the exact trigger still jumps to the top as before — only the identifier-collision case changes.

32. Hotfix build profile
A `hotfix` cargo profile (inherits release, no LTO + incremental + codegen-units 16) for iterating changes into the locally installed app. Release keeps its ship-quality fat LTO + single codegen unit, but that combination re-optimizes the whole dependency graph single-threaded on every bin rebuild — and since Tauri embeds the frontend into the binary, every build (even frontend-only changes) recompiles the app crate and pays it: ~24 minutes warm. Thin LTO measured 13m45s (~9 min compiling the app crate + ~6 min LTO link); no LTO plus incremental compilation brings small-edit rebuilds down to a few minutes, at the cost of losing cross-crate inlining (a few percent on Rust-side work) and a larger exe (~89 MB vs ~70 fat-LTO). The profile builds into its own target dir (target/hotfix, so the release cache stays warm — flipping profile settings per build via env vars would thrash fingerprints and full-rebuild both ways). Build in src-tauri: `pnpm build` then `cargo build --profile hotfix --features custom-protocol`. The feature flag is the trap: `tauri build` normally enables custom-protocol (which makes the app serve the embedded frontend instead of pointing at the dev-server URL), plain cargo does not, and this tauri CLI has no `--profile` flag to get both — a first attempt without it produced a binary that launches fine but shows "localhost refused to connect". Cold builds ~23 min; the first completed no-LTO build (full app-crate compile, no reusable incremental state after a disk-full crash) took 9m54s — the first small-edit rebuild after it is the one that shows the true warm number.

33. Uncheck-all and show-only-filtered in the result grid's Columns dropdown
The column-visibility popover (the "Columns" button above a result grid) gained two bulk actions next to Invert / Reset order / Show all. "Hide all" unchecks every column in one batch — the starting point for hand-picking a few columns out of a wide result. "Show filtered only" is enabled once the popover's search matches something, and makes the visible set exactly the matching columns: matches get checked (including previously hidden ones) and everything else is hidden in one batch — type "user", click, and the grid shows just the user columns. Both ride the grid's existing batch-visibility handle methods (one state commit + one persistence write per click), so every grid hosting the popover (query results, table data, document browser) gets them with no grid-side changes. One rule kept on purpose, matching every other visibility path and the footer's own hint: at least one column always stays visible — "Hide all" leaves the first column checked, because a fully unchecked state is unrepresentable downstream (the visible-index fallback would show all columns while every checkbox reads unchecked). The action row wraps to two lines in the narrow popover; "Show filtered only" grays out with no filter or no matches, "Hide all" when only one column is visible.
